# 신체 부위별 정규화 가이드

현재 저장소의 [오프라인 프로세서](../input_keypoint/bodypart_normalization_processor.py)와 [온라인 정규화 함수](../realtime/inference_utils.py)를 구분하여 설명합니다. 실행 예시는 [빠른 시작](BODYPART_NORM_QUICKSTART.md)을 참고합니다.

## 입력과 좌표 처리

입력은 OpenPose 순서의 `(137, 3)` 배열입니다. 세 번째 값은 confidence이며, 모델에는 최종 x, y 좌표 274개만 전달합니다.

| 부위 | 인덱스 | 처리 |
| --- | --- | --- |
| Pose | 0~24 | 이미지 너비·높이로 나눈 뒤, 코가 유효하면 코 기준 상대 좌표 |
| Face | 25~94 | confidence 임계값을 넘는 점 5개 이상이면 부위별 바운딩 박스 정규화 |
| 왼손 | 95~115 | 같은 조건으로 왼손 바운딩 박스 정규화 |
| 오른손 | 116~136 | 같은 조건으로 오른손 바운딩 박스 정규화 |

부위별 유효점이 5개 미만이면 이미지 크기로 나누는 방식으로 폴백합니다. 바운딩 박스 크기에 하한과 padding이 적용됩니다. 범위 밖의 점을 일괄 clip하지 않으며, Pose 상대 좌표는 음수가 될 수 있습니다. 결과가 정확히 `[0, 1]`이라고 가정하거나 임의로 clip하면 입력 분포가 바뀝니다.

## 오프라인 JSON → CSV

`BodyPartNormalizationProcessor`는 다음 순서로 처리합니다.

1. `*_keypoints.json`을 프레임 번호로 정렬하고 `people[0]`의 키포인트를 읽습니다.
2. JSON 해상도, 좌표 기반 추정, 기본 크기를 이용해 프레임 해상도를 정합니다.
3. 부위별 정규화 후 코 confidence가 0보다 크면 Pose를 상대 좌표로 변환합니다.
4. 시퀀스를 `target_frames` 길이로 선형 보간합니다.
5. `frame` 열과 274개 좌표 열을 CSV에 저장합니다.

주요 생성자 옵션:

| 옵션 | 기본값 | 의미 |
| --- | --- | --- |
| `image_width`, `image_height` | 1920, 1080 | 해상도를 결정하지 못했을 때 기본값 |
| `target_frames` | 180 | 선형 보간 후 길이 |
| `confidence_threshold` | 0.3 | 바운딩 박스 계산에 포함할 점의 임계값 (`>` 비교) |
| `bbox_padding` | 0.1 | 바운딩 박스 양쪽 여유 비율 |
| `enable_multiprocessing` | true | 이름과 달리 현재는 스레드 풀 병렬 처리 |
| `max_workers` | CPU 수와 8 중 작은 값 | 병렬 작업 수 |

최소 2프레임 이상의 유효한 원본 시퀀스를 준비하고, 누락·손상 JSON과 NaN/무한값은 별도로 점검해야 합니다. 이 경로는 WebSocket의 입력 검증·결측점 마스킹을 자동으로 재사용하지 않습니다.

모듈의 `main()`은 `Source_data/9.슬프다`라는 예시 경로를 하드코딩합니다. 그 데이터는 저장소에 없으므로, 경로를 받는 Python API를 사용하는 편이 명확합니다. 이전 문서에서 안내한 `scripts/compare_normalization_methods.py` 및 `integrated_keypoint_processor_optimized.py`는 현재 저장소에 없습니다.

## Flask WebSocket과의 차이

`ai_server.preprocess_frame()`은 브라우저에서 전달한 137 × 3 배열을 `normalize_keypoints_by_bodypart(..., width=1.0, height=1.0)`로 처리합니다. WebSocket 입력 형태·confidence·결측점은 [세션 규약](../../docs/RECOGNITION_PROTOCOL.md)에서 검증합니다.

- 오프라인 프로세서는 픽셀 좌표 기준 바운딩 박스 최소 크기 1.0을 사용합니다. 온라인 함수는 정규화 좌표에 대해 별도 하한을 사용하므로 좌표 단위를 섞으면 안 됩니다.
- Flask는 코 confidence가 0.1보다 클 때 Pose 상대 좌표를 적용합니다. 오프라인 프로세서의 기준은 0보다 큼입니다.
- Flask는 결측 좌표의 마스크를 만들고 NaN/무한값을 0으로 치환합니다. 오프라인 CSV 경로가 같은 결측 처리를 한다고 가정하면 안 됩니다.
- 오프라인 기본 시간축은 180프레임 선형 보간입니다. Flask WebSocket은 128프레임 버퍼를 모델 서비스에 넘긴 뒤 52프레임을 0으로 채웁니다.

따라서 함수 이름이 비슷하다는 이유만으로 학습·실시간 입력이 일치한다고 단정할 수 없습니다. 입력 정책 비교는 평가 데이터와 함께 별도로 확인해야 하며, 여기서는 정책을 변경하지 않습니다.

## 성능 해석과 기존 기록

기존 가이드에는 좌표 범위 확대 예시로 `약 33배`, 외부 프로젝트 기대 효과로 `BLEU +5.9%`, `Accuracy +5.5%`가 적혀 있었습니다. 현재 저장소에는 이를 재현하는 비교 스크립트와 평가 데이터가 없으며, 이 서비스의 정확도 개선을 증명하는 측정값으로 사용하지 않습니다.

정규화는 좌표 표현을 바꾸는 작업입니다. 그 효과를 평가하려면 동일한 데이터 분할·모델·학습 조건에서 변경 전후를 비교하고, 정확도와 클래스별 결과 및 응답 지연을 별도로 측정해야 합니다. 기존 모델의 저장된 검증 수치는 [배포 모델 문서](../deployment/README.md)에 구분하여 기록되어 있습니다.
